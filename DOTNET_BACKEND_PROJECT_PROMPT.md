# .NET 10 Backend Project Setup Prompt for Developer Journal Application

## Project Overview and Requirements

Create a comprehensive .NET 10 Web API backend for a Developer Journal application using Clean Architecture, CQRS pattern with MediatR, and PostgreSQL database. The application allows developers to document their daily work activities, problems faced, solutions implemented, learnings, and best practices. The backend must support JWT-based authentication, provide RESTful API endpoints for user authentication and daily log management, and implement proper validation, error handling, and logging mechanisms suitable for a moderate-level enterprise application.

## Technology Stack and Core Libraries

Use .NET 10 SDK with ASP.NET Core Web API project template. Implement CQRS pattern using MediatR library version 12.x or higher for command and query separation. Use Entity Framework Core 9.x with Npgsql provider for PostgreSQL database access and management. Implement FluentValidation library version 11.x for input validation and business rule enforcement. Use AutoMapper version 13.x for object-to-object mapping between entities and DTOs. Implement JWT authentication using Microsoft.AspNetCore.Authentication.JwtBearer package. Use Serilog for structured logging with console and file sinks. Include Swashbuckle.AspNetCore for Swagger/OpenAPI documentation generation. Add BCrypt.Net-Next for secure password hashing. Use Polly for resilience and transient fault handling if needed.

## Project Structure and Architecture

Organize the solution using Clean Architecture principles with the following project structure: Create DeveloperJournal.Domain project as a class library containing all domain entities, enums, exceptions, and interfaces without any external dependencies. Create DeveloperJournal.Application project as a class library containing all business logic, CQRS commands, queries, handlers, DTOs, validators, mapping profiles, and application service interfaces, with dependencies only on Domain project, MediatR, AutoMapper, and FluentValidation. Create DeveloperJournal.Infrastructure project as a class library containing database context, entity configurations, repository implementations, external service integrations, and infrastructure concerns, with dependencies on Application and Domain projects, Entity Framework Core, and Npgsql. Create DeveloperJournal.API project as the main ASP.NET Core Web API project containing controllers, middleware, filters, API configuration, dependency injection setup, and serving as the application entry point. Ensure proper separation of concerns where Domain contains enterprise business rules, Application contains application business rules and use cases, Infrastructure contains implementation details and external concerns, and API contains web-specific concerns and presentation layer logic.

## Domain Layer Implementation

In the Domain project, create an Entities folder containing User entity with properties: Id as Guid primary key, Name as string with max length 100, Email as string with max length 255 and unique constraint, PasswordHash as string for storing bcrypt hashed password, Role as enum (Developer, SeniorDeveloper, TeamLead, Manager), CreatedAt as DateTime in UTC, UpdatedAt as DateTime in UTC. Create DailyLog entity with properties: Id as Guid primary key, UserId as Guid foreign key referencing User entity, LogDate as DateOnly for the date of the log entry, TasksWorked as string with max length 2000 describing tasks completed, ProblemsFaced as string with max length 2000 describing challenges encountered, Solutions as string with max length 2000 describing solutions implemented, Learnings as string with max length 2000 describing knowledge gained, Tips as nullable string with max length 1000 for optional best practices, GitLink as nullable string with max length 500 for optional repository or commit URL, CreatedAt as DateTime in UTC, UpdatedAt as DateTime in UTC. Include navigation property User in DailyLog entity and collection navigation property DailyLogs in User entity for proper relationship mapping. Create Enums folder with UserRole enum containing values Developer, SeniorDeveloper, TeamLead, Manager. Create Exceptions folder with custom exception classes: DomainException as base exception, EntityNotFoundException for resource not found scenarios, ValidationException for business rule violations, and UnauthorizedException for authentication failures.

## Application Layer - CQRS Commands and Queries

In the Application project, create Features folder organized by entity with separate folders for Commands and Queries. For Authentication feature, create LoginCommand containing Email and Password properties, returning LoginResponse with User details and JWT token. Create LoginCommandHandler implementing IRequestHandler interface, validating credentials, verifying password hash using BCrypt, generating JWT token with user claims (userId, email, role), and returning authenticated user data. Create LoginCommandValidator using FluentValidation to ensure email is required, valid format, and max 255 characters, password is required with minimum 8 characters. For User registration, create RegisterUserCommand containing Name, Email, Password, and Role properties. Create RegisterUserCommandHandler to check email uniqueness, hash password using BCrypt with work factor 12, create new User entity, save to database, and return created user. Create RegisterUserCommandValidator to enforce name required with max 100 characters, email required and valid with max 255 characters and uniqueness check, password required with minimum 8 characters and complexity rules (at least one uppercase, one lowercase, one digit, one special character), and role required and valid enum value.

For DailyLog management feature, create CreateDailyLogCommand containing UserId, LogDate, TasksWorked, ProblemsFaced, Solutions, Learnings, Tips (optional), and GitLink (optional) properties. Create CreateDailyLogCommandHandler to validate user exists, ensure no duplicate log for same date and user, create new DailyLog entity, save to database, and return created log details. Create CreateDailyLogCommandValidator to ensure LogDate is required and not future date, TasksWorked is required with max 2000 characters, ProblemsFaced is required with max 2000 characters, Solutions is required with max 2000 characters, Learnings is required with max 2000 characters, Tips is optional with max 1000 characters, GitLink is optional but must be valid URL format when provided with max 500 characters, and UserId is valid Guid. Create UpdateDailyLogCommand with Id, and optional fields for partial updates. Create UpdateDailyLogCommandHandler to verify log exists, verify user owns the log, update only provided fields, update UpdatedAt timestamp, and return updated log. Create DeleteDailyLogCommand with Id and UserId. Create DeleteDailyLogCommandHandler to verify log exists, verify user owns the log, soft delete or hard delete based on business rules, and return success response.

Create GetAllDailyLogsQuery with UserId parameter returning list of user's daily logs sorted by LogDate descending. Create GetAllDailyLogsQueryHandler to fetch all logs for the user with optional pagination support, include navigation properties efficiently, and return mapped DTOs. Create GetDailyLogByIdQuery with Id and UserId parameters. Create GetDailyLogByIdQueryHandler to fetch specific log, verify user ownership, throw EntityNotFoundException if not found, and return mapped DTO. Create SearchDailyLogsQuery with UserId, Keyword (optional), DateFrom (optional), DateTo (optional) parameters. Create SearchDailyLogsQueryHandler to build dynamic query based on provided filters, search keyword across TasksWorked, ProblemsFaced, Solutions, Learnings, Tips, and GitLink fields, filter by date range when provided, sort results by LogDate descending, and return filtered results with count.

## Application Layer - DTOs and Mapping

Create DTOs folder with separate subfolders for Request and Response DTOs. For requests, create LoginRequestDto with Email and Password, RegisterUserRequestDto with Name, Email, Password, and Role, CreateDailyLogRequestDto with LogDate, TasksWorked, ProblemsFaced, Solutions, Learnings, Tips, and GitLink, UpdateDailyLogRequestDto with optional fields for partial updates, SearchDailyLogsRequestDto with Keyword, DateFrom, and DateTo. For responses, create UserResponseDto with Id, Name, Email, and Role (excluding sensitive data like PasswordHash), LoginResponseDto with User object and Token string, DailyLogResponseDto with Id, LogDate, TasksWorked, ProblemsFaced, Solutions, Learnings, Tips, GitLink, CreatedAt, and UpdatedAt, DailyLogListResponseDto for paginated lists with Items collection, TotalCount, PageNumber, and PageSize properties. Create AutoMapper mapping profiles in MappingProfiles folder to map User entity to UserResponseDto, DailyLog entity to DailyLogResponseDto, request DTOs to command objects, and command objects to entities where needed. Configure proper mapping for DateOnly to string conversions, enum to string conversions, and null handling.

## Infrastructure Layer - Database Context and Configuration

In the Infrastructure project, create Persistence folder with ApplicationDbContext inheriting from DbContext. Define DbSet properties for Users and DailyLogs. Override OnModelCreating method to configure entity relationships, indexes, and constraints. Create EntityConfigurations folder with separate configuration classes implementing IEntityTypeConfiguration interface. For UserConfiguration, configure Id as primary key with default value generation using Guid.NewGuid(), Name as required with max length 100, Email as required with max length 255 and unique index, PasswordHash as required, Role as required enum stored as string, CreatedAt and UpdatedAt with default values and automatic update on modification. For DailyLogConfiguration, configure Id as primary key with default value generation, UserId as required foreign key with cascade delete behavior, LogDate as required with index for efficient querying, all text fields with appropriate max lengths and required constraints, Tips and GitLink as optional fields, CreatedAt and UpdatedAt with default values, composite unique index on UserId and LogDate to prevent duplicate logs for same date, and relationship configuration for User navigation property. Configure table names as "Users" and "DailyLogs" with proper schema if needed.

## Infrastructure Layer - Repository Pattern and Unit of Work

Create Repositories folder with IRepository generic interface defining methods: GetByIdAsync, GetAllAsync, FindAsync with predicate parameter, AddAsync, UpdateAsync, DeleteAsync, and ExistsAsync. Create IUserRepository extending IRepository with additional methods: GetByEmailAsync, EmailExistsAsync. Create IDailyLogRepository extending IRepository with additional methods: GetByUserIdAsync, GetByDateRangeAsync, SearchLogsAsync with filter parameters. Implement Repository generic base class with ApplicationDbContext dependency implementing common CRUD operations using Entity Framework Core. Implement UserRepository and DailyLogRepository classes with specific query methods using efficient LINQ queries and proper includes for navigation properties. Create IUnitOfWork interface with properties for Users and DailyLogs repositories, SaveChangesAsync method returning affected rows count, and transaction support methods BeginTransactionAsync, CommitAsync, and RollbackAsync. Implement UnitOfWork class managing DbContext lifecycle, repository instances, transaction scope, and proper disposal pattern.

## API Layer - Controllers and Endpoints

In the API project, create Controllers folder with base ApiControllerBase inheriting from ControllerBase, decorated with [ApiController] and [Route("api/[controller]")] attributes, injecting IMediator dependency for CQRS pattern. Create AuthController with POST /api/auth/login endpoint accepting LoginRequestDto, sending LoginCommand through MediatR, returning 200 OK with LoginResponseDto on success or 401 Unauthorized with error message on failure, and POST /api/auth/register endpoint accepting RegisterUserRequestDto, sending RegisterUserCommand, returning 201 Created with UserResponseDto and location header on success or 400 BadRequest with validation errors. Create DailyLogsController decorated with [Authorize] attribute for JWT authentication requirement. Implement GET /api/dailylogs endpoint with optional query parameters for pagination (pageNumber, pageSize), sending GetAllDailyLogsQuery with authenticated user's Id from JWT claims, returning 200 OK with paginated results. Implement GET /api/dailylogs/{id} endpoint with id route parameter, sending GetDailyLogByIdQuery, returning 200 OK with DailyLogResponseDto or 404 NotFound if log doesn't exist or doesn't belong to user. Implement POST /api/dailylogs endpoint accepting CreateDailyLogRequestDto, extracting userId from JWT claims, sending CreateDailyLogCommand, returning 201 Created with location header and created resource. Implement PUT /api/dailylogs/{id} endpoint accepting UpdateDailyLogRequestDto, verifying ownership, sending UpdateDailyLogCommand, returning 200 OK with updated resource or 404 NotFound. Implement DELETE /api/dailylogs/{id} endpoint sending DeleteDailyLogCommand with ownership verification, returning 204 NoContent on success. Implement POST /api/dailylogs/search endpoint accepting SearchDailyLogsRequestDto, sending SearchDailyLogsQuery with user context, returning 200 OK with filtered and paginated results.

## Authentication and Authorization Setup

In the API project, configure JWT authentication in Program.cs or Startup.cs by adding Authentication services with JwtBearer scheme, configuring token validation parameters including ValidateIssuer, ValidateAudience, ValidateLifetime, ValidateIssuerSigningKey all set to true, ValidIssuer from configuration, ValidAudience from configuration, IssuerSigningKey created from secret key in configuration using SymmetricSecurityKey, and ClockSkew set to TimeSpan.Zero for precise expiration. Create JwtTokenGenerator service in Infrastructure/Services folder implementing IJwtTokenGenerator interface with method GenerateToken accepting User entity and returning JWT token string. Implement token generation using JwtSecurityTokenHandler, creating claims for user Id as NameIdentifier, email as Email, role as Role, and custom claims as needed, setting token expiration from configuration (e.g., 24 hours), signing credentials using HMACSHA256 algorithm with secret key, and encoding token. Store JWT configuration in appsettings.json with nested object containing Secret (minimum 256-bit key), Issuer (e.g., "DeveloperJournalAPI"), Audience (e.g., "DeveloperJournalClient"), and ExpirationInHours. Register IJwtTokenGenerator with implementation in dependency injection container with scoped lifetime. Configure authorization policies if role-based access control is needed with policies for different user roles.

## Security Best Practices and Additional Considerations

Implement password hashing using BCrypt with appropriate work factor (minimum 12 rounds) to securely store user passwords. Never log or expose sensitive information like passwords, tokens, or personal data in logs or error messages. Use parameterized queries through Entity Framework Core to prevent SQL injection attacks. Validate and sanitize all user inputs at multiple layers using FluentValidation and model binding validation. Implement proper authorization checks in command handlers to verify user ownership of resources before allowing modifications. Use HTTPS only in production by configuring Kestrel or reverse proxy for TLS termination. Store sensitive configuration like JWT secret keys and database passwords in environment variables or secure secret management systems like Azure Key Vault or AWS Secrets Manager in production. Implement audit logging for sensitive operations like user registration, login attempts, and data modifications to track who did what and when. Add request size limits and timeout configurations to prevent denial of service attacks. Implement SQL query result limits and pagination on all list endpoints to prevent performance issues with large datasets. Use async/await pattern consistently for all I/O operations including database access and external service calls. Configure database connection pooling appropriately for expected load. Implement caching strategy using IMemoryCache or distributed cache like Redis for frequently accessed read-only data if needed. Add unit tests for domain logic, command/query handlers, and validators with high code coverage. Consider implementing CQRS with separate read and write models if application scales requiring different optimization strategies for reads versus writes.
